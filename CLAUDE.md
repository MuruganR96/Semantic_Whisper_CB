# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

Research project (GitHub: `MuruganR96/Semantic_Whisper_CB`) on **zero-shot contextual biasing
(hotword boosting) for OpenAI Whisper**: a BPE-token trie drives shallow-fusion logit boosts during
beam search, optionally gated by semantic similarity between Whisper decoder states and Meta SONAR
text embeddings via a fixed linear map `W` — no model training anywhere. All code lives in Jupyter
notebooks; there is no package, build system, linter, or test suite.

**Governance:** the project follows a formal research policy (Phase 0–5: spec → baseline validation →
implementation → smoke test → full experiment → audit). `EXPERIMENT_SPEC.md` is the authoritative
document — hypotheses, frozen conditions, metrics, and success criteria. Read it before changing any
experimental code. Conditions frozen there (decoding parameters, normalization, shard rule, seeds)
must not be changed without the research lead's re-approval, and new experiments need a spec update
before implementation.

## Environment and commands

Local venv (macOS, Apple Silicon) uses Python 3.11 — **not** the Homebrew default 3.14 (no torch
wheels there):

```bash
python3.11 -m venv .venv
./.venv/bin/pip install -U torch transformers datasets scikit-learn scipy pandas matplotlib \
    jiwer soundfile librosa nbformat nbconvert ipykernel
./.venv/bin/pip install sonar-space        # SONAR; requires fairseq2
brew install libsndfile                    # fairseq2 hard-requires it at import time
```

Known pip conflicts that are safe to resolve as: `fsspec<=2026.4.0` (datasets needs it), and
fairseq2's `psutil~=5.9` pin can be ignored (works with psutil 7).

Execute a notebook headless:

```bash
./.venv/bin/python -m nbconvert --to notebook --execute --inplace <notebook>.ipynb \
    --ExecutePreprocessor.timeout=5400
```

Heavy runs (anything decoding audio) are done by the user on a separate CUDA machine; this Mac is
used for authoring. Every experiment notebook has a `FAST` flag that auto-enables on CPU and shrinks
dataset sizes/beams — approval-grade numbers require FAST off / full settings. LibriSpeech is always
consumed via `load_dataset(..., streaming=True)`; never download full splits.

## Notebook chain and artifact dependencies

Chronological chain; later notebooks consume earlier artifacts:

1. `whisper_sonar_alignment_experiment.ipynb` — validates that a linear map Whisper→SONAR exists
   (held-out retrieval ≈ 100%, best decoder layer = 4). Produces **`whisper_to_sonar_W.pt`**
   (`[512, 1024]` tensor), the load-bearing artifact of the whole project.
2. `whisper_trie_sonar_biasing_pipeline.ipynb` — the inference pipeline (trie + state-capture hook +
   `TrieSonarBiasProcessor`) and A/B/C evaluation harness. Consumes `W`; has a fallback cell that
   refits a compact `W` if the file is absent.
3. `whisper_biasing_error_driven_eval.ipynb` — harder evaluation: mines biasing targets from
   certified baseline errors; adds the oracle "gate discriminability" diagnostic.
4. `phase1_baseline_validation.ipynb` — policy Phase 1: reviewer-reproducible B0 baseline on
   dev-clean/dev-other; emits `phase1_config.json`, resumable `phase1_transcripts_*.jsonl`,
   `phase1_shards_*.json` (SHA-256 audited).
5. `phase0_prompt_template_diagnostic.ipynb` — offline SONAR-only prompt-template comparison (H1a);
   no ASR decoding, audio column stripped from the stream.

Notebooks are plain JSON with each cell's `source` as a single string; they were generated by builder
scripts but are edited directly. Result artifacts (`*.csv`, `*.json`, `*.jsonl`, `*.pt`) are written
to the repo root by the notebook that owns them, prefixed by experiment (`phase1_`, `errdriven_`,
`biasing_`, `template_`).

## Cross-notebook invariants (breaking any of these invalidates comparisons)

- **Text normalization** — one function everywhere (mining, WER, recall):
  lowercase → keep only `[a-z' ]` → collapse whitespace. Defined identically in every notebook.
- **Shard rule** — TUNE/DEVTEST split is `sorted(ids)` → `random.Random(42).shuffle` → first 25% =
  TUNE, computed on the *unfiltered* ID list (before the ≤29 s audio filter) so text-only notebooks
  reproduce identical shards. Shard SHAs printed in phase notebooks must match across notebooks.
- **Frozen decoding (spec §6)** — `whisper-base`, beam 5, language/task pinned, no timestamps, and
  `use_cache=False` for **all** conditions (the semantic condition needs full-sequence hidden states;
  baselines match to eliminate the confound). Seed 42 everywhere.
- **Layer indexing** — "layer 4" means `decoder_hidden_states[4]`, which is the output of module
  `model.model.decoder.layers[3]` (hidden_states index 0 is the embedding layer). The forward hook
  uses `best_layer - 1`.
- **Whisper BPE surface forms** — tokenization is context-sensitive: every biasing word must be
  inserted into the trie under 4 forms (`w`, `w.capitalize()`, each with and without a leading
  space), all sharing one hotword id.
- **Silence conditioning** — text-only decoder states are extracted by teacher-forcing over the
  log-mel of 30 s of zeros run through the *feature extractor* (never a raw zeros tensor), with the
  encoder output computed once and reused via `encoder_outputs=`.
- **Recall definition** — occurrence-level, via jiwer word-alignment `equal` chunks after the shared
  normalization. Never substring matching.

## Established empirical findings (do not re-litigate; cite exploratory status)

Recorded so future work builds on them rather than rediscovering them. Per the spec (§9), these are
exploratory numbers — motivation only, not reportable.

- The Whisper→SONAR linear map holds strongly at sentence level (top-1 retrieval ≈ 100% held out;
  all layers saturate on a 400-pool — prefer prefix-probe numbers for layer choice). Prefix states
  degrade gracefully: top-1 ≈ 0.29 at 25% prefix → 1.00 at full sentence.
- **Bare-word SONAR embeddings carry almost no utterance-context signal** (oracle separation 0.028)
  — the motivation for prompt-templated embeddings (H1a). Check
  `template_diagnostic_decision.json` for the current template verdict before assuming a gate works.
- On dev-clean-style data, rarity-mined hotwords are already ~98% recognized by the baseline
  (no headroom); evaluations must use error-driven mining and/or `*-other` splits.
- Unconstrained boosts vandalize transcripts: δ=3 recovered recall 0 → 0.52 but exploded U-WER
  0.128 → 0.700 (orphaned hotword fragments from partial trie matches — no failure-arc revocation is
  implemented). Operating points must be selected under the spec's U-WER constraint; known open
  improvements are first-token boost asymmetry and Aho-Corasick-style bonus revocation.
- LibriSpeech `test-other` was used for exploratory mining and is **quarantined** for final
  reporting; development happens on `dev-clean`/`dev-other` only.

## Conventions

- Every new experiment notebook: markdown explanation cell before each code cell, a `CONFIG` dict up
  top, deterministic seeding, FAST mode on CPU, artifacts saved with an experiment prefix, and an
  interpretation/rubric section at the end mapping outcomes to next actions.
- Commits go straight to `main`; artifacts of long runs (transcripts, CSVs) are committed alongside
  the notebook that produced them for auditability.

## Knowledge wiki (`wiki/` and `raw/`) — schema

The repo carries an LLM-maintained research wiki (the "LLM Wiki" pattern). Claude writes and
maintains **all** of `wiki/`; the user curates `raw/` and asks questions. Start any wiki work by
reading `wiki/index.md`; `wiki/overview.md` holds the evolving thesis.

**Layers.** `raw/` = immutable sources — read, never modify. `wiki/` = generated markdown, owned by
Claude. This section = the schema.

**Structure.** `wiki/{concepts,entities,experiments,sources,process}/` + `overview.md`, `index.md`,
`log.md`. Kebab-case filenames; source pages prefixed `src-`, experiment pages `exp-NN-`. Pages
cross-link with Obsidian wikilinks `[[page-name]]` (filename only, no folder). Every page has YAML
frontmatter: `type` (concept|entity|experiment|source|process|meta), `tags`, `updated`; source pages
add `raw:` and `ingested:`; experiment pages add `notebook:` and `status:`.

**Operations.**
- *Ingest:* user drops a source in `raw/` → read it → discuss takeaways → write
  `wiki/sources/src-*.md` (claims + their fates, defects found) → update every affected concept/
  entity/experiment page and `overview.md` → update `index.md` → append to `log.md`. Never modify
  the raw file.
- *Query:* read `index.md` first, drill into pages, answer with wikilink citations. Answers worth
  keeping (comparisons, analyses, new connections) are filed back as wiki pages — explorations
  compound.
- *Lint:* on request, sweep for contradictions between pages, claims superseded by newer
  experiments, orphan pages, missing cross-references, and concepts mentioned but lacking pages;
  log the pass.

**Log format.** Append-only, newest last: `## [YYYY-MM-DD] <op> | <title>` with
`<op>` ∈ {ingest, query, lint, seed, experiment, decision}. Experiment outcomes and spec/lead
decisions get entries, not just source ingests.

**Discipline rules.** Experiment pages carry their exploratory/reportable status (spec §9) — never
launder exploratory numbers into unqualified claims. When new evidence contradicts a page, update
the page *and* note the supersession explicitly rather than silently rewriting. `index.md` and
`log.md` are updated in the same pass as any page change.
